\section{System Architecture Overview}

The \textbf{Autonomous BDR GTM Platform} is an enterprise-grade agentic sales development system. It pairs an asynchronous \textbf{LangGraph multi-agent pipeline} with a local-first \textbf{Python REST/RPC server} (\texttt{server.py} and Vercel serverless \texttt{api/index.py}), a terminal-based \textbf{Interactive ANSI Dashboard} (\texttt{main.py} / \texttt{cli/dashboard.py}), and a lightweight \textbf{Web Console} supporting Google Workspace OAuth2 and local workbook (\texttt{.xlsx}) persistence via the Chrome/Edge File System Access API.

\subsection{Security Guardrails for Outbound Messaging}
The \texttt{check\_send\_guardrails(payload)} routine strictly enforces multi-layer safety before executing live sends:
\begin{enumerate}
    \item \textbf{Payload Verification}: Requires non-empty \texttt{to}, \texttt{subject}, and \texttt{body}.
    \item \textbf{Suppression Enforcement}: Immediately halts if prospect has \texttt{suppressed} or \texttt{unsubscribed} flags.
    \item \textbf{Mandatory Approval}: Requires strict \texttt{approved === True}.
    \item \textbf{Deduplication}: Generates $\text{SHA256}(\text{to} \parallel \text{subject} \parallel \text{body})$ and verifies non-existence in \texttt{sent\_emails}.
    \item \textbf{Throttling}: Rejects sends exceeding \texttt{PROTOTYPE\_DAILY\_SEND\_LIMIT} (default: 25/day).
\end{enumerate}

\section{Data Models \& Persistence Architecture}

\subsection{SQLite Storage Model (\texttt{.prototype-data/gtm.sqlite3})}
\begin{itemize}
    \item \textbf{\texttt{app\_state (key TEXT PK, value TEXT, updated\_at TEXT)}}: Serialized state store for web console records.
    \item \textbf{\texttt{google\_connections (id INTEGER PK, session\_id, email, name, access\_token, refresh\_token, expires\_at, updated\_at)}}: Stores OAuth tokens encrypted at rest with Fernet symmetric cipher (derived from \texttt{TOKEN\_ENCRYPTION\_KEY}).
    \item \textbf{\texttt{sent\_emails (id INTEGER PK, fingerprint TEXT UNIQUE, recipient, subject, provider\_id, sent\_at)}}: Audit ledger preventing duplicate message transmission.
\end{itemize}

\subsection{Local Workbook Mode (\texttt{.xlsx})}
Using the browser's File System Access API, the app establishes direct two-way binding with a local Excel file containing 10 auditable sheets: \texttt{Contacts}, \texttt{Companies}, \texttt{Enrichment}, \texttt{Campaigns}, \texttt{Activities}, \texttt{Approvals}, \texttt{Events}, \texttt{Settings}, \texttt{Runs}, and \texttt{Metadata}. Provider API keys are never committed to the workbook.

\section{State Schema \& Memory Management}

\subsection{\texttt{BDRState} Schema Definition (\texttt{agents/state.py})}
\begin{lstlisting}[language=Python]
from typing import TypedDict, List, Dict, Any, Annotated
import operator

class BDRState(TypedDict):
    icp_definition: Dict[str, Any]             # Target industries, employee size, geography
    accounts: List[Dict[str, Any]]             # Identified target accounts
    contacts: List[Dict[str, Any]]             # Target buying committee contacts
    sequences: Dict[str, Any]                  # Active campaigns & outreach copy
    email_outbox: List[Dict[str, Any]]         # Dispatched emails audit log
    linkedin_actions: List[Dict[str, Any]]     # Dispatched social touches audit log
    intent_scores: Dict[str, int]              # Calculated engagement intent scores
    qualification_status: Dict[str, Dict]      # BANT qualification results
    crm_records: Dict[str, Any]                # Mirrored HubSpot records (deals, meetings)
    human_approval_queue: List[Dict[str, Any]] # Human-in-the-loop intercept queue
    metrics: Dict[str, Any]                    # Operational telemetry metrics
    logs: Annotated[List[str], operator.add]   # Monotonic append-only log stream
    current_agent: str                         # Active executing agent
\end{lstlisting}

\subsection{LangGraph Checkpointing \& Human-in-the-Loop Interception}
The workflow is compiled using \texttt{SqliteSaver} (persisted to \texttt{.prototype-data/langgraph.sqlite}) or \texttt{MemorySaver}:
\begin{lstlisting}[language=Python]
compiled_graph = builder.compile(
    checkpointer=memory,
    interrupt_before=[
        "campaign_launch",      # Intercept high-value outreach email copy
        "linkedin_engagement",  # Intercept personalized LinkedIn notes
        "crm_intelligence"      # Intercept meeting logs and deal values
    ]
)
\end{lstlisting}
When execution hits an interrupted node, state is snapshotted under \texttt{thread\_id}. The user inspects the queue via CLI or Web UI, mutates the state via \texttt{graph.update\_state(config, ...)}, and calls \texttt{graph.invoke(None, config)} to resume.

\section{Client Invocation \& RPC Execution Flow}

\subsection{\texttt{main.py} Execution Engine}
\begin{enumerate}
    \item \textbf{Initialization}: Compiles LangGraph instance and binds a unique execution session \texttt{thread\_id} (\texttt{"bdr-<uuid>"}).
    \item \textbf{First Run / Resume}: Invokes \texttt{graph.invoke(initial\_state, config)} on cold launch, or \texttt{graph.invoke(None, config)} when resuming from an approval breakpoint.
    \item \textbf{Interrupt Handling}: If \texttt{state\_snapshot.next} hits a breakpoint node, execution yields control to \texttt{cli.dashboard.render\_dashboard(state)}.
    \item \textbf{Approval Processing}: Operators approve, reject, or edit content. \texttt{update\_current\_state()} commits approved items back into the checkpointer before the next cycle resumes.
\end{enumerate}

\subsection{Client-to-Server RPC Sequence}
\begin{lstlisting}[language=bash]
[Web Console / CLI Client]
           |
           |  POST /api/google/gmail/send
           |  Body: { "to": "...", "subject": "...", "body": "...", "approved": true }
           v
[ProxyHTTPRequestHandler (server.py)]
           |
           +-- 1. Read 'gtm_session' cookie & decrypt OAuth tokens via Fernet
           +-- 2. Auto-refresh Google access token if within 60s of expiration
           +-- 3. Execute check_send_guardrails() (Deduplication & rate limit check)
           +-- 4. Make HTTP RPC to Gmail API (https://gmail.googleapis.com/v1/...)
           +-- 5. Write SHA-256 fingerprint into sent_emails table in gtm.sqlite3
           \-- 6. Return HTTP 200 { "id": "msg_xxx", "status": "sent" }
\end{lstlisting}
